# 2. ARCHITECTURE DECISION

## 2.1 Preferred implementation for v0.0.1

Start with a native dockable ScriptUI panel written in ExtendScript.

Reasons:

- After Effects 2024 already supports ScriptUI panels.
- They can appear in the Window menu.
- They can be docked like native panels.
- They can access AE scripting APIs.
- They can create Expression Controls.
- They can generate and assign expressions.
- They require no native C++ effect binary.
- Deployment is relatively simple.
- They fit the requested Support Files backup mirror.

A ScriptUI panel is the preferred baseline, not an excuse to produce an ugly or inconvenient interface.

Build the best ergonomic UI the technology reliably supports.

- A threshold expression does not implement genuine peak hold.
- Mapping amplitude through ease() does not inherently provide temporal attack/release envelopes.
- Stereo channels do not provide frequency-separated bass, mids, and highs.
- Audio Spectrum visualization is not automatically a usable frequency-band signal source.
- Expressions referencing hardcoded layer names can break after renaming.
- Expressions that replace Scale or Position absolutely may destroy intended base animation behavior.
- Unbounded sampling and repeated valueAtTime calls can become expensive.
- Different property value types cannot share arbitrary return expressions.
- Expressions designed for 2D layers may require adaptation or rejection on 3D layers.
- Separated Position dimensions require different treatment from combined Position.
- Random expressions must behave deterministically during repeatable evaluation where appropriate.
- Missing effects, layers, markers, keyframes, or audio controllers must be handled correctly.

Fix the underlying mathematics or architecture.

Do not preserve mistakes for the sake of matching the original Bible exactly.

Keep the original formula in source provenance and document the corrected implementation.

- SHA-256 hash.
- Product version.
- Build identity.

A successful primary install with a failed mirror is not a fully successful deployment.

Attempt safe recovery within the authorized scope.

Report mismatches.

## 14.5 Recovery

Implement an explicit repair command capable of restoring a validated owned build from the recovery mirror.

Before restoring, verify:

- Mirror file integrity.
- Expected product identity.
- Version compatibility.
- Destination ownership.
- Preservation of unrelated files.

# 16. REQUIRED END-TO-END ACCEPTANCE SCENARIOS

The release should satisfy these practical scenarios.

**Scenario A — Basic Scale**

Select a 2D layer, apply breathing scale, adjust frequency and amount, and verify the layer animates without destroying its original scale.

**Scenario B — Audio Scale**

Provide a valid audio amplitude source, apply Beat Scale Pump, change intensity and threshold, and verify the response.

**Scenario C — Multiple Layers**

Select several layers, apply a common behavior, and verify each receives correct controllers without unintended cross-layer changes.

**Scenario D — Shared Master**

Create one shared controller driving several layers. Update the shared parameter and verify synchronized behavior.

**Scenario E — Existing Keyframes**

Apply an additive expression to an already-animated property. Verify the original motion remains intact.

**Scenario F — Expression Conflict**

Select a property with a foreign expression. Verify it is preserved unless a safe explicit operation is chosen.

**Scenario G — Reapply**

Apply the same effect twice. Verify no duplicate controllers or expression conflicts appear.

**Scenario H — Effect Stack**

Apply a compatible pair of behaviors to one property and verify deterministic combined output.

**Scenario I — Missing Audio**

Attempt an audio-dependent recipe without a valid source. Verify that the panel gives a precise diagnostic instead of silently installing a broken expression.

**Scenario J — Removal**

Remove a vac34_AE effect and verify unrelated layer data remains intact.

**Scenario K — Presets**

Save a tuned rig preset, load it onto another compatible layer, and verify the configured behavior.

**Scenario L — Build and Mirror**

Build a release, deploy it to the verified ScriptUI location, mirror it to the specified V: recovery tree, and verify byte-identical deployed artifacts.

**Scenario M — Project Persistence**

Save and reopen an AE project. Verify the generated expressions and native controller values still work without the vac34_AE panel being open.

**Scenario N — Performance**

Apply representative procedural effects to a reasonably sized test composition and check for excessive expression evaluation or panel latency.

Do not declare the release production-verified while required executable acceptance scenarios remain untested.

# 20. PRODUCT PHILOSOPHY

vac34_AE is meant to become a permanent consolidated After Effects automation and expression system.

The long-term architecture must permit future addition of:

- New expression recipes.
- New control types.
- New composite rigs.
- More sophisticated audio analysis.
- Custom procedural animation systems.
- Larger preset libraries.
- Optional modern frontend technology.
- Additional compatible After Effects versions.

However, the first release must remain sharply focused on a usable expression studio.

Avoid premature complexity.

Do not spend the entire implementation budget designing hypothetical future plugins while the basic Apply button is still broken.

The guiding principle is:

**One panel. Many behaviors. Minimal configuration effort. Safe, editable, reusable results.**

The user should be able to work with motion and audio-reactive animation instead of fighting expression code.

Build the product, verify it, publish it to the correct installation, synchronize the mirror, and report the real outcome.
